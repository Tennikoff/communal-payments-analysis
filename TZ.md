# Техническое задание: Система анализа коммунальных платежей

## 1. Цель проекта

Создание веб-сервиса для жильцов многоквартирных домов, позволяющего отслеживать коммунальные платежи, выявлять переплаты путём сравнения с нормативами потребления и прогнозировать расходы на основе исторических данных.

**Проблема:** Жильцы часто переплачивают за коммунальные услуги из-за некорректных начислений, не замечают резких скачков потребления и не могут спланировать бюджет.

**Решение:** Система автоматически анализирует введённые платежи, сравнивает их с нормативами, строит графики динамики расходов и прогнозирует будущие платежи.

---

## 2. Роли пользователей

### Гость (неавторизованный пользователь)
- Просмотр главной страницы с описанием сервиса
- Просмотр общей статистики (средние тарифы по регионам)

### Зарегистрированный пользователь
- Добавление своей квартиры с указанием площади, количества проживающих
- Ввод данных о платежах через форму (дата, тип услуги, сумма, показания счётчиков)
- Просмотр персональной аналитики:
  - График расходов по месяцам
  - Сравнение факта с нормативами
  - Выявление переплат (выделение красным)
  - Прогноз расходов на следующий месяц
- Экспорт данных в CSV

### Администратор
- Управление справочниками (типы услуг, тарифы)
- Модерация данных пользователей через админ-панель

## 3. Модели данных

### 3.1 Apartment (Квартира)
**Описание:** Данные о квартире пользователя

**Поля:**
- `user` (ForeignKey → User) — владелец
- `address` (CharField) — адрес
- `area` (DecimalField) — площадь в м²
- `residents_count` (IntegerField) — количество проживающих
- `created_at` (DateTimeField) — дата добавления

---

### 3.2 ServiceType (Тип коммунальной услуги)
**Описание:** Справочник видов услуг

**Поля:**
- `name` (CharField) — название (Электроэнергия, Водоснабжение, Отопление, Газ)
- `unit` (CharField) — единица измерения (кВт·ч, м³, Гкал)
- `norm_per_person` (DecimalField) — норматив потребления на человека
- `description` (TextField) — описание

---

### 3.3 PaymentRecord (Запись о платеже)
**Описание:** Конкретный платёж по услуге

**Поля:**
- `apartment` (ForeignKey → Apartment) — квартира
- `service_type` (ForeignKey → ServiceType) — тип услуги
- `date` (DateField) — дата платежа (месяц)
- `consumption` (DecimalField) — фактическое потребление
- `tariff` (DecimalField) — тариф на момент оплаты (руб/ед.)
- `total_amount` (DecimalField) — итоговая сумма
- `is_overpayment` (BooleanField) — флаг переплаты (рассчитывается автоматически)

---

### 3.4 Tariff (История тарифов)
**Описание:** История изменения тарифов по услугам

**Поля:**
- `service_type` (ForeignKey → ServiceType)
- `region` (CharField) — регион
- `price` (DecimalField) — стоимость за единицу
- `valid_from` (DateField) — дата начала действия
- `valid_to` (DateField, null=True) — дата окончания (если null — актуален)

## 4. Ключевой функционал (User Stories)

### 4.1 Регистрация и добавление квартиры
Пользователь регистрируется, заходит в личный кабинет и добавляет квартиру (адрес, площадь, количество жильцов).

### 4.2 Ввод данных о платежах
Пользователь через форму вводит:
- Тип услуги (выбор из списка)
- Месяц и год
- Показания счётчика (или сумму)
- Тариф

Система автоматически рассчитывает сумму и сравнивает с нормативом.

### 4.3 Аналитика и выявление переплат
На странице "Аналитика" пользователь видит:
- **Таблицу платежей** с выделением переплат (если потребление > норматив × кол-во жильцов)
- **График столбчатый** (Matplotlib/Plotly): расходы по месяцам с разбивкой по услугам
- **График линейный**: динамика потребления электроэнергии/воды

### 4.4 Прогноз расходов
Система на основе последних 3-6 месяцев данных рассчитывает средний расход и выводит:
Прогноз на следующий месяц:

Электроэнергия: ~850 руб
Вода: ~620 руб
Итого: ~1470 руб

### 4.5 Сравнение с другими пользователями
Вывод средней статистики по всем пользователям сервиса (анонимно):

Средний расход электроэнергии на человека в вашем регионе: 78 кВт·ч
Ваш расход: 95 кВт·ч (+22%)

## 5. Внешние интеграции / Аналитика

### 5.1 Библиотеки анализа данных
- **Pandas:** 
  - Расчёт средних значений, медианы, стандартного отклонения
  - Группировка платежей по месяцам/услугам
  - Выявление аномалий (резкие скачки)

- **Matplotlib / Plotly:**
  - График динамики расходов (линейный)
  - Столбчатая диаграмма расходов по услугам
  - Круговая диаграмма структуры платежей

### 5.2 Расчётные алгоритмы
- **Определение переплаты:**
  ```python
  норма = норматив_на_человека × кол_во_жильцов
  if фактическое_потребление > норма * 1.1:  # +10% допуск
      is_overpayment = True

Прогноз методом скользящего среднего:

прогноз = среднее(последние_3_месяца) × текущий_тариф

### 5.3 Внешнее API
Интеграция с API открытых данных для получения актуальных тарифов по регионам РФ (например, data.gov.ru).

### 8. Критерии успеха
-Пользователь может за 2 минуты добавить квартиру и первый платёж
-Система корректно выявляет переплату (тестовый сценарий: ввод 200 кВт·ч при норме 70)
-Графики строятся корректно при наличии 3+ записей
-Прогноз рассчитывается с точностью ±15%
-Код соответствует PEP8, нет дублирования
